# Caliber 지원을 위한 AI Works 포트폴리오 강화 설계

## 목표

공개 `AI Works` 페이지를 단순 영상 아카이브에서 이미지, 영상, 글을 기획부터 최종 납품까지 직접 완성하는 AI 콘텐츠 크리에이터의 증거 중심 포트폴리오로 강화한다. 특정 회사 전용 페이지처럼 보이지 않게 유지하면서도 Caliber AI 콘텐츠 크리에이터 공고의 평가 기준을 담당자가 첫 화면과 대표 사례에서 바로 확인할 수 있게 한다.

핵심 평가 기준은 다음과 같다.

- 좋은 결과물과 아쉬운 결과물을 구도, 색감, 디테일, 브랜드 적합성 관점에서 구분하고 이유를 설명한다.
- 첫 생성 결과에 멈추지 않고 후보 비교, 리테이크, 편집, QC를 통해 완성도를 높인다.
- 이미지, 영상, 글을 서로 분리된 결과가 아니라 하나의 브랜드 언어로 설계한다.
- 프로젝트를 brief부터 final delivery까지 직접 이끈다.

## 제외 범위

- Caliber 이름을 전면에 내세운 지원 전용 URL 또는 전용 랜딩 페이지
- 연락 유도 CTA 추가
- 사이트 전체 리브랜딩
- 기존 33개 영상 작업 또는 기존 상세 URL 삭제
- 검증할 수 없는 성과 수치 추가
- 모든 기존 작업에 새로운 과정 자료를 소급 제작하는 작업

## 기본 언어

- 저장된 언어 선택이 없는 최초 방문자는 한국어를 기본값으로 사용한다.
- 기존 영어 전환 기능과 선택 기억 기능은 유지한다.
- 한국어와 영어 카피가 모두 있는 기존 작업은 그대로 사용하고, 신규 대표 사례도 양쪽 언어의 핵심 내용을 제공한다.

## 핵심 메시지

상단 헤드라인은 다음 메시지를 전달한다.

> 이미지·영상·글을 하나의 브랜드 언어로 만듭니다.

보조 문구는 브랜드의 콘셉트, 이미지, 영상, 카피를 하나의 방향으로 설계하고 첫 생성 결과에 멈추지 않고 수정해 완성한다는 점을 설명한다. 특정 채용 공고의 문장을 그대로 복제하지 않는다.

상단에는 다음 세 역량을 짧게 표시한다.

- Image: 콘셉트 이미지, 캐릭터와 제품의 비주얼 시스템
- Video: 기획, 생성, 연출, 편집, 사운드
- Writing: 보이스 설계, 리서치, 카피와 블로그 제작

## AI Works 정보 구조

### 1. Hero

- 핵심 헤드라인과 보조 문구
- `Image`, `Video`, `Writing` 세 가지 역량 표시
- 현재 확인 가능한 범위에서 `33 Projects`, `Concept → Delivery`와 같은 사실만 사용
- CTA는 배치하지 않는다.

### 2. Featured capabilities

세 분야를 같은 무게로 보여주되 작업물 특성에 맞게 서로 다른 레이아웃을 사용한다.

#### Video

- `Only What You Want` — Bose QuietComfort
- `2026 World Cup Edition` — Kling과 Hailuo 기반 제품 컬렉션 필름
- `The Great Wave / Don't Press This Here…` — Blender 움직임 레퍼런스와 Seedance 제작
- `Step Out in Color` — 영상과 이미지 제작 과정이 연결되는 교차 사례

#### Image

- Step Out 캐릭터 후보와 identity-locked 최종 캐릭터
- 다섯 컬러웨이의 제품 및 의상 레퍼런스 시트
- Bose 캐릭터 룩과 제품 컬러 락
- Yena 시리즈의 캐릭터, 작품, 장소 일관성 이미지

각 이미지 묶음에는 결과를 선택한 기준을 `구도`, `색감`, `디테일`, `브랜드 적합성` 중 필요한 항목으로 짧게 설명한다. 단순 이미지 썸네일 모음으로 만들지 않는다.

#### Writing & Systems

##### i.do.eats voice building

- 실제 작성 샘플에서 화자, 독자, 톤, 문장 리듬과 금지 표현을 추출한 과정
- 보이스 규칙이 적용되기 전과 후의 짧은 글 비교
- 재사용 가능한 Naver Blog voice system으로 정리된 결과

##### Naver Blog production workflow

- `Research → Voice draft → Humanize → Mobile formatting → Image plan → Final QA`
- 제목 후보, 본문, 사진 순서와 커버 이미지를 한 콘텐츠 패키지로 제작하는 방식
- 최신 정보와 개인 경험을 분리하고, 확인되지 않은 경험을 만들지 않는 검증 기준
- 내부 자동화의 복잡성보다 콘텐츠 판단과 품질 관리가 먼저 읽히도록 표현

### 3. Production method

전체 제작 방식을 다음 여섯 단계로 설명한다.

1. Brief
2. Visual system
3. Generate
4. Review
5. Refine
6. Deliver

각 단계는 사용하는 툴보다 판단 기준과 산출물을 먼저 설명한다.

### 4. Archive

기존 33개 작업을 유지한다. 최초 진입 시 추천 작업이 먼저 보이도록 하고, 분류는 채용 담당자가 역량을 빠르게 이해할 수 있는 다음 기준으로 변경한다.

- Featured
- Video
- Image
- Writing & Systems
- Character IP
- Experiments

`Yoonjae & Gia`, `Yena`는 삭제하지 않고 보조 태그로 유지한다.

## 대표작 상세 페이지

대표작은 다음 공통 구조를 사용한다. 해당 증거가 없는 프로젝트에서는 빈 섹션을 노출하지 않는다.

### 1. Final result

- 완성 영상 또는 최종 이미지
- 한 문장 콘셉트
- 담당 범위, 제작 연도, 사용 도구와 최종 규격

### 2. Brief

- 무엇을 만들었는지
- 브랜드 또는 콘텐츠가 해결해야 했던 문제

### 3. Creative decision

- 구도, 색감, 디테일, 브랜드 적합성 가운데 핵심 판단
- 최종 방향을 선택한 이유

### 4. Process

- 기획 문서
- 스토리보드 또는 레퍼런스
- 핵심 프롬프트 또는 보이스 규칙
- 생성, 편집과 QC 과정

자료는 가로 스크롤 또는 비대칭 그리드로 보여준다. 장식용 그래픽보다 실제 제작 자료를 사용한다.

### 5. Iteration

`초안 → 문제 → 수정 → 최종` 순서를 사용한다.

- Bose: Take 1, 2, 3 비교와 엔드카드 선택
- Step Out: 스토리보드 v1에서 v4, 캐릭터 후보에서 identity-locked 최종본
- Great Wave: Blender 움직임 레퍼런스, 음악 음량 v1에서 v2, 자막과 업스케일 QC
- Voice/Naver Blog: 초안, 보이스 규칙 적용, Humanizer와 모바일 포맷 결과

비교 자료에는 무엇이 달라졌는지와 왜 최종안을 선택했는지를 한두 문장으로 기록한다.

### 6. Final delivery

- 최종 규격, 러닝타임, 언어와 납품 형태
- 확인 가능한 결과만 사용하고 성과를 추정하지 않는다.

### Prompt disclosure

현재 상세 페이지의 긴 원문 프롬프트가 결과물보다 먼저 시선을 가져가는 문제를 해결한다. 핵심 프롬프트와 판단을 본문에 보여주고, 전체 원문은 접힌 `전체 프롬프트 보기` 영역에서 제공한다. 프롬프트 파일이 없는 작업은 진행 중이라는 빈 패널 대신 해당 영역을 생략한다.

## 시각 디자인

방향은 `크리에이티브 디렉터의 콘택트시트 + 제작 노트`이다.

- 기존의 따뜻한 아이보리와 검정 중심 팔레트를 유지한다.
- 여러 파스텔 아이콘 카드는 제거하고 한 가지 절제된 포인트 컬러만 사용한다.
- 큰 타이포그래피, 실제 작업 이미지, 작은 제작 메모를 조합한다.
- 결과물은 크게, 도구명과 버전 정보는 작은 모노스페이스 글자로 표현한다.
- 실제 스토리보드, 후보안과 QC 이미지를 화면의 질감과 정보로 사용한다.
- 섹션마다 같은 카드 패턴을 반복하지 않고 영상, 이미지와 글의 성격에 맞는 레이아웃을 사용한다.
- 진입 및 스크롤 공개 애니메이션은 작업물 재생과 비교를 방해하지 않는 범위로 제한한다.
- `prefers-reduced-motion` 사용자는 불필요한 움직임을 보지 않게 한다.

## 데이터와 컴포넌트 구조

기존 React, TypeScript, Tailwind와 Motion 스택을 유지한다. 프레임워크를 교체하거나 새 UI 라이브러리를 추가하지 않는다.

### Work data

기존 `PortfolioWork` 데이터에 다음 정보를 선택적으로 추가한다.

- media types: video, image, writing, system
- featured rank
- capability tags
- process assets
- iteration comparison pairs
- creative decision
- final delivery facts

신규 글 및 시스템 사례도 같은 상세 페이지 셸을 재사용할 수 있게 데이터 중심으로 구성한다.

### Components

- `AIWorks`: 홈의 요약 대표작
- `WorkGallery`: 역량 기반 전체 아카이브
- `WorkDetail`: 상세 페이지 셸
- `CapabilityIntro`: 세 분야 소개
- `FeaturedCaseStudies`: 분야별 대표 사례
- `ProcessRail`: 실제 제작 자료 흐름
- `IterationCompare`: 초안과 최종 비교
- `PromptDisclosure`: 전체 프롬프트 접기/펼치기

컴포넌트는 자료가 없을 때 섹션 전체를 생략하며 깨진 이미지나 빈 카드가 남지 않게 한다.

## 에셋 사용 계획

확인된 원본 자료에서 웹에 필요한 파일만 선별해 프로젝트 `public` 아래로 복사하고 원본 폴더는 수정하지 않는다.

- Bose: storyboard, character/product references, take QC sheets, font/end-card options
- Step Out: storyboard v1–v4, character candidates and locked finals, product sheets, final 4K master
- Great Wave: Blender renders, subtitle and upscale QC, selected edit variants
- World Cup: existing final master and poster; 추가 과정 자료가 확인되지 않으면 결과 및 제작 설명만 제공
- Voice/Naver Blog: voice profile excerpts, title/body/image-plan examples and approved images; 민감 정보와 로컬 경로는 공개하지 않는다.

웹 공개용 에셋은 파일명을 정리하고 적절한 크기로 최적화한다. 사용자 개인 경로, API 정보와 내부 자동화 자격 증명은 포함하지 않는다.

## 반응형과 접근성

- 데스크톱의 비대칭 그리드는 모바일에서 논리적 읽기 순서의 단일 열로 변환한다.
- 비교 이미지는 모바일에서 위아래로 배치하고 `초안`, `최종` 레이블을 유지한다.
- 모든 의미 있는 이미지에 구체적인 대체 텍스트를 제공한다.
- 버튼과 링크는 키보드 포커스 표시를 제공한다.
- 영상은 사용자의 명시적 재생을 기본으로 하고, hover preview는 음소거 상태로 유지한다.
- 색상만으로 초안과 최종 상태를 구분하지 않는다.

## 오류 및 빈 상태

- 이미지 또는 영상 로딩 실패 시 레이아웃이 무너지지 않는 대체 표면과 설명을 사용한다.
- prompt 파일 fetch 실패 시 오류 문구를 해당 disclosure 내부에 표시한다.
- 과정 자료가 없는 작업은 `archive in progress`와 같은 빈 패널을 표시하지 않고 섹션을 생략한다.
- 존재하지 않는 slug는 현재의 branded 404와 전체 작업 복귀 동작을 유지한다.

## 검증

### 기능

- 기존 모든 상세 URL과 내비게이션 정상 작동
- 최초 방문 한국어 기본값과 언어 전환 및 선택 기억
- 역량 필터와 추천 정렬
- prompt disclosure 열기, 닫기와 fetch 실패 상태
- 키보드로 카드, 필터와 disclosure 접근

### 시각

- 데스크톱, 태블릿과 모바일 주요 화면 확인
- 영상, 이미지와 긴 글의 비율 및 줄바꿈 확인
- 초안과 최종 레이블 및 설명이 원본과 일치하는지 확인
- hover가 없는 터치 환경에서도 작품 제목과 유형이 보이는지 확인

### 기술

- production build
- TypeScript 또는 build-time 오류
- console error
- 깨진 로컬 media 경로
- 기존 route 회귀

## 완료 기준

- AI Works 첫 화면에서 이미지, 영상과 글 세 역량이 스크롤 초반에 명확히 보인다.
- 대표작에서 최종 결과뿐 아니라 선택 기준과 수정 이유를 확인할 수 있다.
- Bose, Step Out, Great Wave, World Cup, Voice Building과 Naver Blog 사례가 계획한 범위로 제공된다.
- 기존 33개 작업과 상세 URL이 유지된다.
- 한국어가 최초 기본 언어이고 영어 전환이 정상 작동한다.
- 모바일, 키보드와 reduced-motion 환경에서 핵심 콘텐츠를 이용할 수 있다.
- production build와 주요 브라우저 검증이 통과한다.
